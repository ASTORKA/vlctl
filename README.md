# vlctl

Минималистичный CLI-клиент для `vless://` ссылок (VLESS / REALITY / XTLS-Vision) на Linux и macOS.
Один Python-файл, только стандартная библиотека, без GUI и без Qt/AppImage — то есть без того,
на чём обычно ломаются Nekoray и Hiddify.

Своей реализации протокола внутри нет и не планируется: REALITY — это подменённый TLS-хендшейк
с uTLS-отпечатком браузера и X25519-аутентификатором, писать его с нуля бессмысленно.
`vlctl` разбирает ссылку, генерирует JSON-конфиг и запускает готовое ядро:

| Режим | Ядро | Что делает | root |
|---|---|---|---|
| SOCKS (по умолчанию) | xray-core | SOCKS5 `127.0.0.1:10808` + HTTP `:10809` | не нужен |
| TUN (`--tun`) | xray-core + sing-box | весь трафик системы через VPN, перехват DNS | нужен |

В TUN-режиме протокол говорит xray, а sing-box работает как tun2socks: принимает пакеты
из TUN-интерфейса и отдаёт их в локальный SOCKS от xray. Так REALITY выполняет та же
реализация, что и в SOCKS-режиме, — реализация sing-box отстаёт от свежих версий Xray
и на некоторых серверах отдаёт `reality verification failed`. Побочный плюс: в TUN
работают и транспорты, которых у sing-box нет (`xhttp`).

Флаг `--native` включает старую схему, где sing-box сам говорит на VLESS.

Формат конфига sing-box выбирается по версии установленного ядра: 1.12+ получает новый
формат DNS-серверов, 1.11 и старее — legacy.

## Установка

```bash
git clone <этот-репозиторий> ~/vlctl
ln -s ~/vlctl/vlctl.py ~/.local/bin/vlctl     # если ~/.local/bin в $PATH
vlctl install                                  # скачает xray-core в ~/.local/share/vlctl/bin
vlctl install --sing-box                       # ядро для TUN-режима (по желанию)
```

Нужен Python 3.8+ и `curl` (для команды `test`). Если ядро не найдено при запуске,
утилита сама предложит его скачать.

## Интерактивный режим

Просто:

```bash
vlctl
```

Покажет список сохранённых подключений (последнее использованное подставляется по умолчанию —
достаточно нажать Enter), предложит добавить новую ссылку или импортировать подписку.
При добавлении ссылки спрашивается название; по умолчанию берётся имя из `#`-фрагмента.
Название всегда можно поменять потом — пункт «Переименовать».

Для выбранного подключения доступно: подключиться (SOCKS), VPN-режим (TUN),
проверить внешний IP, переименовать, показать ссылку/конфиг, удалить.

Ссылку можно передать сразу — откроется тот же диалог сохранения:

```bash
vlctl 'vless://uuid@host:443?security=reality&...#Швеция'
```

## Команды для скриптов

```bash
vlctl up   <ссылка|профиль> [--tun]      # поднять подключение (Ctrl+C — остановить)
vlctl test <ссылка|профиль>              # какой IP и страну видит внешний мир
vlctl config <ссылка|профиль> [--tun]    # напечатать JSON-конфиг ядра
vlctl save <имя> <ссылка>
vlctl rename <старое> <новое>
vlctl rm <имя>
vlctl ls
vlctl import <url|файл>                  # подписка: список ссылок или base64
vlctl doctor [профиль]                   # часы, ядра, /dev/net/tun, доступность сервера
vlctl install [--sing-box]
```

Полезные флаги: `--socks-port`, `--http-port` (`0` — не поднимать HTTP), `--dns` (для TUN), `-v`.
Порт занят — утилита молча возьмёт свободный и напечатает какой.

Использование SOCKS-прокси после `vlctl up`:

```bash
export ALL_PROXY=socks5h://127.0.0.1:10808
curl https://ifconfig.co/json
```

В браузере — SOCKS5 `127.0.0.1:10808` с включённым «DNS через прокси».

## Что поддерживается из ссылки

`security`: reality, tls, none · `flow`: xtls-rprx-vision · `type`: tcp, ws, grpc, httpupgrade, xhttp ·
параметры `sni`, `fp` (uTLS-отпечаток), `pbk`, `sid`, `spx`, `alpn`, `path`, `host`, `serviceName`,
`headerType`, `allowInsecure`.

Другие протоколы (vmess, trojan, shadowsocks) намеренно не поддерживаются.

## Где что лежит

- профили: `~/.config/vlctl/profiles.json` (права 600)
- ядра: `~/.local/share/vlctl/bin/`
- конфиги ядра создаются во временном файле на время работы и удаляются при выходе

## Частые вопросы

**Подключился через пункт 1, а IP на сайте проверки не поменялся.**
Так и должно быть: SOCKS-режим — это прокси, а не VPN. Он работает только для приложений,
которым этот прокси указан. Сразу после старта `vlctl` сам проверяет туннель и печатает,
какой IP видно *через прокси* — если там нужная страна, всё в порядке. Чтобы IP менялся
везде, включая браузер, запущенный до этого, нужен TUN-режим (пункт 2 / `--tun`).

**TUN-режим с `--native` пишет «недоступно для этого сервера».**
sing-box не умеет транспорт `xhttp` и маскировку `headerType=http`. В обычном
(не `--native`) TUN-режиме это неважно — там протоколом занимается xray.

**`reality verification failed`.**
Сервер не признал REALITY-аутентификацию и отдал сертификат маскировочного сайта.
Причины: разошлись системные часы (в хендшейк зашита метка времени — расхождение
в пару минут ломает всё), неверный `pbk`, неверный или отсутствующий `sid`, не тот `sni`.
Начни с `vlctl doctor <профиль>` — он сверит время и проверит доступность сервера.
Если ошибка только в TUN-режиме с `--native`, а SOCKS работает — это расхождение
реализаций REALITY; обычный TUN-режим этим не страдает.

**`FATAL legacy DNS servers is deprecated`.**
Старая версия vlctl генерировала конфиг под sing-box 1.11. Обнови: `git pull`.
